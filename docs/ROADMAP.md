# 项目路线图

## 总目标

构建一个允许用户上传带原唱歌曲、生成伴奏和参考旋律、实时显示演唱音高并在结束后给出可解释评分的 Web 应用。

## 里程碑 1：音高评分基线（已完成）

- [x] 初始化 Git 和 Python 项目结构
- [x] PCM WAV 读取与写入
- [x] YIN 单音音高检测
- [x] 整体录音延迟估计
- [x] 规则评分与 SVG 音调线
- [x] 合成音频与自动测试
- [x] 导入第一批真实手机录音并生成质量画像
- [x] 使用三首原唱和手机录音校准真实人声参数
- [x] 使用受约束 DTW 处理不同前奏与局部速度变化
- [x] 输出可审计的时间映射和对齐质量诊断

验收标准：使用一组参考人声和用户清唱 WAV，稳定输出音高轨迹、对齐结果和分项评分。

## 里程碑 2：歌曲预处理

- [x] 安装并封装 FFmpeg
- [x] 使用 Demucs 对真实手机录音完成两段 30 秒人声分离验证
- [x] 完整分离《七里香》并生成混录/人声/伴奏诊断报告
- [x] 将 Demucs 封装为应用内异步任务
- [x] 从完整混音生成 vocals 和 accompaniment
- [x] 为耗时任务加入进度、缓存和错误处理
- [x] 建立 3 首自有测试歌曲的首轮回归样本

## 里程碑 3：离线 Web MVP（进行中）

- [x] FastAPI 上传与分析接口
- [ ] React + TypeScript 前端
- [x] 文件校验和后台处理状态
- [ ] 结果页面、浏览器音高曲线和逐段反馈
- [x] 本地数据目录、失败恢复和隐私边界文档

## 里程碑 4：实时 K 歌

- 使用 Web Audio API 播放伴奏和采集麦克风
- AudioWorklet 音频分帧
- 客户端实时音高检测
- Canvas 实时绘制参考线和用户线
- 设备延迟校准
- 唱后服务端高精度复算

## 里程碑 5：评分模型与评测

- 建立人工分项评分数据集
- 比较规则、树模型和时序模型
- 按歌手和歌曲分组划分数据集
- 报告 MAE、相关性、跨设备稳定性和推理成本
- 只有在数据证明必要时微调音高检测模型

## 里程碑 6：部署与作品集

- Docker 化与持续集成
- 可复现演示数据
- 性能、延迟与模型评测报告
- 在线演示或完整演示视频
- 架构说明、已知限制与简历项目描述

## 当前非目标

- 歌词自动识别与逐字同步
- 社交、排行榜、支付和复杂账号体系
- 修音、美声或实时音效
- 原生移动端应用
- 在没有数据基线时从头训练大型模型
