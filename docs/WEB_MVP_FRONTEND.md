# Web MVP 前端说明

## 技术栈

- React 19 + TypeScript
- Vite 8
- 原生 SVG 音调线
- MediaRecorder + Web Audio API
- 客户端 YIN 实时音高检测
- Vitest + Testing Library
- Playwright 真实浏览器验收

前端位于 `frontend/`。开发服务器把 `/api` 代理到本机 `127.0.0.1:8000`，所以电脑和同一局域网内的手机都只需要访问前端端口。

## 用户流程

1. 上传原唱音频。
2. 查看异步分离与参考音高生成进度。
3. 播放伴奏，在 20 秒移动窗口中查看原唱人声音调线。
4. 选择“完整演唱”或“选取段落”；片段模式默认推荐原唱人声最密集的 30 秒，也可用双滑块调整。
5. 可选运行约 4 秒的设备延迟校准；使用当前手机扬声器播放三组短促扫频音，并从麦克风回录中估计稳定的往返延迟。
6. 允许麦克风后从所选起点播放伴奏并实时查看自己的音高；不支持麦克风时可上传对应范围的已有录音。
7. 到达所选终点时自动停止并上传本次录音。
8. 查看总分、音准、节奏、完整度、稳定性和音高对比图。

界面状态由 `useKaraokeWorkflow` 管理，后台任务由 `useJobPolling` 轮询。歌曲详情和音高数据并行加载，避免串行等待。

实时演唱由 `useLivePerformance` 管理。音高检测模块只在用户点击开始后动态加载；麦克风波形通过 `AnalyserNode` 每 80 毫秒取样，YIN 检测结果只保留约 22 秒的可视窗口，避免持续增长和不必要的 React 重渲染。录音格式根据浏览器能力在 M4A、WebM 和 OGG 中选择。音调线的纵轴中心只由当前窗口内的原唱人声中位音区决定，用户唱偏不会带动参考坐标移动。

设备校准由 `useLatencyCalibration` 和 `audio/latencyCalibration.ts` 管理。校准时关闭回声消除、降噪和自动增益，优先通过 `AudioWorklet` 捕获原始 PCM，旧浏览器回退到 `ScriptProcessorNode`。三次归一化互相关结果至少需两次可信且最大离散不超过 80 毫秒，随后取中位数并按浏览器缓存七天。实时音高点会减去该延迟后写入歌曲时间轴；原始 MediaRecorder 文件不裁剪，避免与服务端 DTW 重复补偿。

## 响应式布局

- 桌面端：左侧歌曲和播放控制，右侧大幅音调线画布。
- 手机端：控制区与音调线纵向排列，按钮保持足够触控面积。
- 评分页：桌面双栏、手机单栏；对比图自动缩放，不产生页面横向滚动。
- 实时演唱页：手机纵向单画布；桌面左侧控制、右侧大画布。

## 验证

组件测试覆盖初始上传、非法文件拦截、完整/片段模式、片段范围保留、局部原唱音区居中、实时演唱准备与文件回退、延迟校准入口、从歌曲上传到评分结果的完整状态流，以及客户端 YIN 对 110–659 Hz 稳定音高和静音的检测。纯算法测试会把校准信号插入带噪声的合成麦克风录音，验证 185 毫秒延迟恢复、三次结果聚合、异常离散拒绝、浏览器缓存和时间轴补偿。

```powershell
pnpm --dir frontend lint
pnpm --dir frontend test
pnpm --dir frontend build
```

真实浏览器验收使用 1440×1000 桌面视口和 390×844 手机视口，检查关键页面截图、页面横向溢出、控制台错误和失败请求。真实音频端到端验证使用 `reference/七里香-周杰伦-94237-100.ogg` 与 `myvoice/七里香.m4a`，本次基线结果为总分 79、音准 69、节奏 93、完整度 93、稳定性 92。

实时演唱验收通过 Chrome 虚拟麦克风注入一段项目内人声音频，验证麦克风授权、连续实时音高、伴奏同步、MediaRecorder 产物和 multipart 自动提交。测试录音超过 70 KB，未绕过录音或音高检测代码。

## 浏览器与安全连接

- Chrome、Edge 和 Safari 的现代版本支持实时演唱所需 API。
- 麦克风仅在安全上下文可用：`localhost` 或有效 HTTPS。
- 手机通过普通局域网 HTTP 访问时，界面会说明限制并保留“上传已有录音”。
- 正式线上部署必须使用 HTTPS；外放时先校准并将手机远离音箱，佩戴耳机可减少伴奏串入麦克风。

## 当前限制

- 当前实时取帧使用 `AnalyserNode`；后续可迁移至 AudioWorklet，进一步降低主线程抖动。
- 浏览器无法可靠识别用户何时切换了输出设备，因此切换扬声器、耳机或蓝牙后需要手动重新校准；封闭式耳机使校准音无法进入麦克风时可直接跳过。
- 同一演唱录音重复提交仍会重新处理，后续应增加演唱结果哈希缓存。
- 分数是可解释规则基线，尚未通过人工评分数据训练或校准。
