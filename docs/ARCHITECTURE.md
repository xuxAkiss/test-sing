# 混合部署架构

## 原则

手机负责需要即时反馈的轻量工作，服务端负责耗时、耗电和依赖大型模型的工作。实时音调线不能依赖移动网络往返，完整歌曲分离也不应阻塞手机或持续消耗电池。

## 手机端

- 播放预处理后的伴奏
- 通过麦克风采集用户演唱
- 使用 AudioWorklet、WebAssembly 或原生音频回调分帧
- 运行轻量 YIN/小型音高模型
- 绘制实时参考线与用户音调线
- 记录原始演唱并在结束后上传
- 保存设备延迟校准值

实时音频回调中不执行网络请求、文件写入或重模型推理。

## 服务端

- FFmpeg 格式转换
- Demucs 人声/伴奏分离
- 从原唱生成标准旋律
- 对完整用户录音做高精度音高复算
- DTW 时间对齐和最终评分
- 缓存歌曲预处理结果

## 数据流

```text
歌曲上传 → 服务端预处理 → 伴奏 + 标准音高线
                              ↓
                    手机播放和实时反馈
                              ↓
用户录音上传 → 服务端高精度复算 → 分项评分与逐句反馈
```

## 当前原型映射

- `audio_engine/separation.py`：服务端人声分离任务
- `audio_engine/pitch.py`：当前 Python 音高检测基线，后续移植轻量版本到客户端
- `audio_engine/alignment.py`：服务端全局延迟和整八度偏移估计
- `audio_engine/dtw.py`：服务端长音频受约束 DTW 与逐段时间映射
- `audio_engine/scoring.py`：可解释规则评分 baseline

第一版采用响应式 Web/PWA 客户端；验证音频链路后再决定是否开发原生 iOS/Android 客户端。
